# Telegram UX Guidelines

## Назначение

Эти правила обязательны для всех пользовательских экранов ThreadFlow в
Telegram. Они относятся к текстам, callback-кнопкам, FSM-сценариям и
уведомлениям из `bot`, `api` и `worker`.

## Язык и терминология

- Интерфейс по умолчанию полностью на русском.
- Названия Radar, Neuro и Brain допустимы как названия функций. Их статусы,
  настройки и пояснения должны быть по-русски.
- Внутренние имена Python, SQL и Threads API не выводятся пользователю.
- Используются единые названия: «Лимит в день», «Минимальная оценка»,
  «Пауза между действиями», «Ключевые слова», «Сначала спрашивать»,
  «Автоматически», «Подходящий пост», «Источник».
- Статусы переводятся: `pending` — «Ожидает», `publishing` — «Публикуется»,
  `done`/`posted` — «Опубликовано», `failed` — «Ошибка», `unknown` —
  «Результат не подтверждён».

## Структура экрана

- Каждый account-scoped экран показывает выбранный `@username`.
- Сложный раздел в одном-двух предложениях объясняет назначение.
- На экране не более 5-7 основных действий. Расширенные настройки выносятся
  на отдельный экран.
- После статуса или результата показывается следующий рекомендуемый шаг.
- Кнопки `⬅️ Назад` и `🏠 Главная` находятся в последнем ряду клавиатуры.
- Пустое состояние объясняет, почему данных нет и как они появятся.
- Сообщение разбивается на короткие блоки по 3-5 строк и читается без
  горизонтальной прокрутки.
- Числа форматируются как `245 000`, `1,2 млн`, `4,8%`.
- Даты и время показываются в часовом поясе аккаунта, не в UTC.

## Режимы интерфейса

- Новый пользователь начинает в простом режиме.
- Существующий пользователь после миграции сохраняет полный доступ через
  продвинутый режим.
- Режим интерфейса не связан с тарифом и не меняет автоматические действия.
- Простой режим показывает Dashboard, Автопилот, Аналитику, аккаунты,
  настройку, баланс и тариф.
- Продвинутый режим дополнительно открывает Radar, Neuro, Brain, ручное
  планирование и расширенные настройки.

## Ошибки и пустые состояния

- Пользователь видит: что произошло, потеряны ли данные и что делать дальше.
- Нельзя показывать raw exception, SQL, stack trace, токены, OAuth state,
  внутренний request ID или необработанный ответ Threads API.
- Временная ошибка не должна утверждать, что операция точно не произошла.
- Для неподтверждённой публикации запрещён автоматический повтор.
- Если отдельный блок Dashboard недоступен, остальные блоки продолжают
  отображаться.

## Безопасность действий

- Любой account ID из callback проверяется вместе с `user_id`.
- Опасные действия требуют отдельного подтверждения с точным аккаунтом и
  последствиями.
- После успешного изменения кнопки заменяются или становятся идемпотентными.
- Повторное нажатие получает ответ «Уже выполняется» или «Уже выполнено».
- Автоматический режим Neuro включается только после явного подтверждения.
- Очистка очереди показывает число удаляемых постов и предупреждает, что
  кредиты не возвращаются.

## FSM и onboarding

- Каждый ввод объясняет формат, приводит пример и сообщает способ отмены.
- FSM хранит account ID шага и отклоняет сохранение после смены аккаунта.
- Onboarding показывает номер шага, сохраняет прогресс и поддерживает
  «Назад», «Пропустить» и «Продолжить позже».
- Настройка не списывает кредиты и не включает автоматические комментарии
  без явного согласия.

## Проверка нового экрана

Перед merge автор проверяет русский текст, длину сообщения, пустое состояние,
account isolation, ownership callback, возврат на предыдущий экран, отсутствие
секретов, повторное нажатие и поведение при частично недоступных данных.
